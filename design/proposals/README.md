# 新方案提案（proposals/）

> 本目录只存**尚未进入实现计划**的新方案。它是「想法区」，不是路线图：
> 任何文档在实现落地前都不代表现有功能，不得写进 flows / specs，更不得让用户误以为已经存在。

## 每份提案必须写清

1. **状态**：proposed（本目录只有这一种状态；确认后迁出）
2. **目标**：想解决什么问题、给谁
3. **非目标**：明确不做什么，防止范围漂移
4. **方案概述**：交互与视觉怎么长
5. **待确认问题**：需要用户 / 产品拍板的点
6. **转入 decisions 的条件**：什么信号出现时升级为正式决策并拆实现计划

## 生命周期

```
proposed ──用户确认方案──▶ 拆实现计划 ──实现+验收──▶ 决策记入 decisions/，本目录文件删除或归档
   │
   └──被否决──▶ 标记 rejected（保留一个月供追溯，之后删除）
```
