# 提案 · 可重播分步功能引导（replayable product tour）

- **状态**：**proposed —— 尚未实现，未进入任何实现计划**。本文描述的是设想，不是现有功能。
- **提出**：2026-10-24（用户在整理设计知识库时提出的新方向）

## 目标

新同学第一次打开工具就能被牵着走完「登录 → 选活动 → 开始计划」主线；
老同学随时能从「使用说明」重新播放引导，自己找回某个功能在哪。

## 非目标

- 不做视频教程、不做联网帮助页（工具离线可用，帮助也离线）。
- 不替代现有首次说明弹窗的内容维护，只决定它怎么被「分步」呈现。
- 不引导服务器版功能（本机工具范围外）。

## 方案概述

1. **首次使用自动启动**：首次打开且未登录时，自动进入第 1 步引导（代替一次性静态弹窗）。
2. **遮罩 + 区域高亮**：半透明遮罩盖住全界面，只挖出当前步骤指向的区域（登录按钮、时刻表、
   筛选栏、计划区、开始按钮、运行记录），说明气泡贴在旁边。
3. **导航**：「上一步 / 下一步 / 跳过」；顶部小进度点（第 2 / 5 步）；Esc 等同跳过。
4. **可重播**：右上角「使用说明」入口提供「再看一遍引导」；换新版本后引导带**版本号**，
   功能有实质变化时升级版本并允许再放一次（`ui.json` 记 `tour_version`）。
5. **边界处理**：
   - 未登录 / 空列表：引导只讲静态区域，不依赖列表数据；
   - 窄窗口（≤980 视口）：气泡改为底部条，不用旁贴；
   - 计划运行中：自动暂停引导（优先不打扰运行状态），结束后可继续；
   - **Chrome 登录窗口是系统窗口，工具高亮不了**——这一步只能文字说明「会弹出 Chrome，
     输学号 / 密码 / 验证码」，不能遮罩标注。

## 待确认问题

1. 引导步骤清单（建议 5 步：登录 → 时刻表与模式标签 → 筛选 → 勾选与冲突 → 开始计划与停止）；
2. 遮罩视觉沿用候车厅琥珀还是中性灰（琥珀有「正等着你」语义，但可能与运行态混淆）；
3. 版本升级触发规则（每次发版 / 仅功能实质变化）；
4. 跳过后是否永不再自动弹（建议：是，只留手动入口）。

## 转入 decisions 的条件

用户确认步骤清单与视觉方向后：先补一条 decisions 记录（引导是正式产品行为），
再拆实现计划（涉及 `local/ui/` 全部三个文件与 `ui.json` 新键，需独立计划与验收）；
实现验收通过后本文从 proposals/ 删除。
