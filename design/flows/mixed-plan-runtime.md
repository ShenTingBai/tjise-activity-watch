## 运行中的界面

| 区域 | 显示什么 |
|---|---|
| 计划摘要 | 已安排 N 场：X 场预报名等开放，Y 场立即报名马上执行 |
| 任务卡 | 每场独立状态（waiting / submitting / 终态）+ 自己的模式标签；提交中显示「第 N 次提交 · 最近原因 · 重试截止 · 报名截止」 |
| 五站路线图 | 本次启动 / 活动页已打开 / 盯按钮 / 原定开放 / 本次重试到——**前三个只显示真实事件时间**，没发生显示「待启动 / 待打开 / 待发生」 |
| LED 大屏 | 倒计时与统一截止（`effectiveRetryDeadline`），与任务卡、终态同源 |

## 独立调度（修复前后的差异）

**修复前**（2026-10-25 之前的缺陷，仅作历史对照）：

- 协调器把预报名场阻塞到 `sign_start` 才启动 worker，`--lead 100` 在计划模式下形同虚设；
- 前端拿计划时间（原定开放前 100 秒 / 前 5 秒）冒充「活动页已打开」「盯按钮」的显示时间；
- 一个场次的重试会 join 整批，拖住后续批次在自己的准备时刻启动。

**修复后（现行）**：

- 协调器按每场准备时刻调度：预报名在原定开放前 `lead_s`（默认 100 秒）启动 worker，
  立即报名在计划启动后马上执行，同一准备时刻的场次一起启动；
- worker 提前启动后**立即真实打开详情页**，开放前 5 秒进入盯按钮，开放后才提交；
- 批次之间不 join：一场在重试中，另一场照样按自己的时刻启动；
- 路线图只消费真实 checkpoint（`run_started_at` / `page_opened_at` / `watch_started_at`），
  缺失就显示占位文本，不编时间。

## 页面重载恢复

| # | 用户动作 | 系统状态 | 可见反馈 | 失败后的下一步 |
|---|---|---|---|---|
| R1 | 计划运行中刷新页面（F5）/ 锁屏回来 | `bootstrap()` 附带 plan 快照（静态字段 + 运行时 checkpoint） | 任务列表、「停止」按钮、路线图上的真实事件时间**原样恢复** | —— |
| R2 | （无动作） | 恢复只回放显示，不重新提交 | 提交只发生在「开始报名计划」那一刻；旧结果不会被当新结果重播 | —— |

快照缺运行时字段时，前端 `mergeTask` 合并而不是覆盖——已经收到的 checkpoint 不会被空值抹掉。

## 已知边界

- 修复后的机制有 fake clock 单测（118/118）与 demo EXE 截图证据；
  **有效登录下**「开放前 100 秒真实开页、前 5 秒盯按钮」的真机确认留给用户（见 [007 已知限制](../decisions/007-runtime-timeline.md)）。
