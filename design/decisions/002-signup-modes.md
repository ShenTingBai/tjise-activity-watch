# 002 · 双报名模式与已截止

- **状态**：implemented（规则 confirmed 2026-10-25）
- **日期**：2026-10-25 由用户确认为正式产品口径（此前复盘曾误判「开放后执行」为偏差，已更正）

## 问题

工具同时服务两种场景：提前把未来活动排进计划等开放，和报名已开放时立即去抢。
早期设计（单活动、只等原定时刻）无法表达这两种意图，还可能把已截止活动当成能报的。

## 用户确认的规则

1. 报名状态分三类，唯一口径是 `signup_plan.classify_signup_mode(sign_start, sign_end, now)`：
   - **pre_register（预报名）**：`sign_start` 在未来——提前加入计划，工具在原定开放前约 100 秒启动这一场，开放后才提交；
   - **instant_signup（立即报名 / 抢名额）**：已开放且未截止——选中后马上执行，重试窗口从本次启动起算；
   - **closed（已截止）**：`sign_end` 能解析且已过去——只能查看，不能加入计划。
2. `sign_start` / `sign_end` **只**决定报名模式；活动举办时间 `act_start` / `act_end` **只**用于举办时段冲突检查，
   不参与报名资格判断——活动已经开演或演完，只要报名窗口还开着就能报。
3. `sign_end` 缺失或非法时按安全回退处理（instant_signup + 重试窗口回退），**不得**当成已截止。
4. 已截止活动保留在「全部」列表查看；勾选、整行点击、前端校验、后端校验、开始计划五层一致拒绝，
   拒绝信息带活动名与截止时间。
5. 存在未报名的开放活动时，大屏目标场与快捷「选这一场」优先开放活动，其次才是未来最近一场。
6. 模式在计划创建时定格进任务快照（`TaskSpec.signup_mode`），之后时间推移不改写快照。

## 用户可见行为

- 每行、任务卡、大屏摘要都标模式：预报名 / 立即报名·抢名额 / 已截止。
- 勾选已截止活动：复选框禁用、点击被拦、开始前报「报名已截止」。
- 混合计划里两种模式共存、逐场显示、互不阻塞（一场重试中，另一场照样按自己的时刻启动）。
