- **问题**：新同学第一次打开工具看不懂主线，老同学找不到「这个功能在哪」；静态三步弹窗一次性、不可回看。

## 用户确认的规则

1. **六步主线**（顺序固定）：登录状态 → 活动与模式 → 筛选 → 选择与冲突 → 重试与开始 → 运行与结果。
2. **首次自动开始**：第一次打开（或引导内容升版）自动进入第 1 步；看过同一内容版本（完成或跳过）不再自动弹。
3. **两处并列重播**：「更多 → 重看引导」与「说明 → 重看引导」随时从头播放，两处共用同一条路径
   （先确认非忙、关掉当前弹窗、把焦点还给对应顶栏入口，再 `startTour(0)`）。历史变更：入口原只在
   说明弹窗，2026-10-25 随 [决策 010](010-standalone-exe-and-settings.md) 迁入「设置」，本轮返修
   再改为「说明 + 更多」并列；说明弹窗保留三步快速帮助——说明不是「更多」的替代，两者并列。
4. **引导版本独立，且版本归属只认内容版本**：`tour_version` 表示引导内容版本（**当前 2**：返修轮把第 2/5/6 步的实质误导改掉，属于内容变化，故 1→2；更早的行为修正轮不升版），与软件版本（VERSION 文件）互不绑定；软件从 1.0.2 升到 1.1.0 **不**提升 `TOUR_VERSION`。自动开始只按「已看过的内容版本号」判定：完成/跳过时间戳只描述当时那一版，**不得挡住更新的内容版本**（返修前旧时间戳会永久拦截新版引导，已修正）。
5. **视觉**：中性遮罩 + 琥珀色高亮框（沿用候车厅琥珀语义），说明卡片带步骤号、进度点、上一步/下一步/跳过/完成。
6. **键盘与窄窗**：Esc 等同跳过且只落一次跳过记录；引导**可见且未暂停**时 Tab/Shift+Tab 在卡片按钮间首尾循环，背景 Ctrl+F、`/`、Enter 被隔离（不移焦点、不开始计划；卡片内 Enter 走按钮原生激活）；关闭/跳过/完成时恢复引导开始前的焦点；窄窗口（≤980）或目标缺失/隐藏时退回底部静态说明条，不伪造定位。
7. **边界**：计划运行中自动暂停引导（优先不打扰运行状态；暂停期间键盘约束全部放行，不挡「停止」），结束后从原步骤继续；主界面重画（`render()`）导致目标挪动时重新定位现有高亮，不重开、不自动点击；引导绝不代替用户点登录、选活动或开始报名；**Chrome 登录窗口是系统窗口，只能文字说明，不能高亮**。
8. **状态保存**：`tour_version` / `tour_completed_at` / `tour_skipped_at` 写入 `ui.json`（与界面偏好同一文件、同一把持久化锁），完成/跳过立即落盘。

## 用户可见行为

- 首次打开：直接进入六步引导（不再先弹静态三步说明）；说明弹窗仍可随时从顶栏「说明」打开。
- 跳过后：下次打开不自动弹；点「更多 → 重看引导」或「说明 → 重看引导」都可再看（两处是同一条路径）。
- 引导内容变化（升版）后：即使跳过过旧版，也会再自动弹一次新版。
- 引导打开时：Tab 只在「跳过引导 / 上一步 / 下一步」间循环，Ctrl+F、`/`、回车不会窜到主界面；Esc 关闭后焦点回到之前的位置。
- 计划运行中：引导自动隐藏（此时键盘一切照常），计划结束后回到原来的步骤。

## 已知限制

- 引导高亮只在工具窗口内有效；系统弹窗（Chrome 登录窗）无法高亮，只能文字说明。
- 视觉定位（遮罩贴合、卡片位置）需用户真机验收；本轮只有 mock 渲染截图证据，不等于有效登录真机验收。
- 行为回归（node vm 装置）已定义未运行（返修轮同样只写不跑，授权范围不含执行测试）；运行后才有红绿证据。

## 变更方式

- 调整步骤文案/顺序：改 `local/ui/app.js` 的 `TOUR_STEPS`；实质变化时 `TOUR_VERSION += 1`。
- 增删高亮目标：改 `local/ui/index.html` 的 `data-tour-target` 与 `TOUR_STEPS[].target`，同步更新 TourAndLifecycleContractTests。
- 视觉样式：`local/ui/styles.css` 的 `.tour-*` 段（遮罩/高亮/卡片/底部条）。
