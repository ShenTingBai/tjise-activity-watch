# 007 · 运行时间线：真实事件 + 原定参考 + 统一截止

- **状态**：implemented（机制已落地并有自动化证据；**有效登录下的真机验收待用户**）
- **日期**：规则 confirmed 2026-10-25；提前调度与真实 checkpoint 修复同日落地
  （计划 `20261024-preopen-checkpoint-repair`，全量单测 118/118、demo EXE 截图证据）

## 问题

时间线曾经混用三种性质完全不同的时间：计划算出来的时间、真实发生的事件、策略推导的截止，
前端还拿计划时间冒充「活动页已打开」「盯按钮」——用户看到的像进度，其实是编的。

## 用户确认的规则

1. **五个站点、三种来源**：

   | 站点 | 来源 | 缺失时显示 |
   |---|---|---|
   | 本次启动 | worker 真正启动那一刻（`run_started_at`，真实事件） | 待启动 |
   | 活动页已打开 | 详情页真正加载完成（`page_opened_at`，真实事件） | 待打开 |
   | 盯按钮 | 真正进入按钮监视（`watch_started_at`，真实事件） | 待发生 |
   | 原定开放 | 学校给的 `sign_start`，**参考节点**，不因提前准备而改变 | —— |
   | 本次重试到 | 起算点 + 你设的时长，被 `sign_end` 截断（`retry_deadline`） | —— |

2. **界面只显示真实事件**：未发生的节点显示「待启动 / 待打开 / 待发生」占位文本，
   **不得**用计划时间（原定开放前 100 秒 / 前 5 秒）或当前时间生成看起来像已发生的时间。
3. **checkpoint 先到先得**：`run_started_at` / `page_opened_at` / `watch_started_at` / `retry_deadline`
   第一次写入后，迟到或重放的事件不得改写；空值不落库；页面重载恢复不丢（快照 + `mergeTask` 合并）。
4. **统一有效截止**：路线图、任务卡、LED、终态文案共用 `effectiveRetryDeadline`——telemetry 优先，
   否则按 `retry_for_s`（0=直到 `sign_end`，缺截止回退 120 秒）推导，`sign_end` 永远截断。
5. **慢页面不吃掉重试窗口**：重试起算点在打开页面前固定（`retry_anchor`）——
   已开放场次从 worker 启动时刻起算，页面加载慢几十秒，用户设置的 10 分钟还是完整的 10 分钟。
6. **预报名提前准备**：协调器按每场准备时刻调度——预报名在原定开放前 `lead_s`（默认 100 秒，快照携带）启动 worker，
   worker 立即打开详情页、开放前 5 秒进入盯按钮、开放后才提交；「原定开放前 100 秒」是**计划准备时刻**，
   路线图不把它显示成事件。
7. 历史「原定开放」是参考节点照常标完成，但不得抢占当前执行节点；已过去的历史时间显示完整日期。

## 用户可见行为

- 任务卡与路线图的「本次启动 / 活动页已打开 / 盯按钮」永远是真实发生时间；没发生就是占位文本。
- 已开放场次页面再慢，重试截止也停在「启动时刻 + 你设的时长」不动。
- 预报名场次在开放前约 100 秒能看到「本次启动」「活动页已打开」先亮起来，「盯按钮」要等开放前 5 秒才亮。

## 决策 012 修订（2026-10-26 返修轮更新）：全部真实节点同业务北京时间

- 「本次启动 / 活动页已打开 / 盯按钮 / retry_deadline」等 checkpoint 的时刻读数与
  截止比较全部按**独立北京时间**（业务 epoch + 经过时长）记录与展示；
  「原定开放」等学校参考节点不再被本机系统时钟提前改写（`--at` 改写、
  分类、接纳窗口、监督截止同源业务时钟）。
- 运行中重校只影响单次读数的不确定度，不改写已落库的历史 checkpoint 事实；
  系统墙钟跳变 ±8 小时 / ±30 天不影响节点显示与倒计时
  （QA：clock-skew-boot-8h / clock-skew-boot-30d / wall-jump-during-plan /
  clock-skew-runtime-minus8h）。

## 变更方式

站点语义或字段改动需同步 `local/signup_plan.py`（`CHECKPOINT_FIELDS`）、`local/grab.py`（事件输出）、
`local/ui/app.js`（`paintRoute` / `effectiveRetryDeadline` / `mergeTask`）、`docs/UI_SPEC.md` §5.10 与本记录；
`run_started_at` 等四个字段名不得重命名（快照与事件契约）。

## 2026-10-26 返修补记（1.1.1 候选）

节点时间改由 worker 的 `[checkpoint]` 源事件提供，父层另存 `worker_spawned_at`；计划策略起点、worker 入口、页面打开、盯按钮与父层接收时刻分开表达。


## 决策 012 修订（2026-10-26）：时间线 epoch 来自统一业务时钟

节点仍只来自真实事件（worker_started/page_opened/watch_started），但事件 at 与调度、截止监督全部使用独立北京时间（网络锚点+经过时长）；原定开放是参考时刻，重校产生的新锚点带新 generation，不修改历史 checkpoint。
