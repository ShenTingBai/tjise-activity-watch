# 011 · 单帮助入口与手动检查更新

- **状态**：confirmed，代码已落地；技术验证与用户视觉验收分开登记。
- **日期**：2026-10-25。

## 问题

「说明」与「更多」都提供重看引导，内容少却让用户在两个模态间查找；大块浅黄色强调区
也偏离了主界面站牌与时刻表的视觉。现有「查看发布页」只打开链接，不进行版本比较。

## 用户确认与采用方案

用户允许合并可合并的内容、重做主题一致的辅助弹窗，并要求检查此前讨论的更新能力。
采用一个顶栏「帮助」与一个模态，三步操作在前、版本和数据在后；不增加页面导航层级。
主题用黑色站牌标题、冷灰白纸、细分隔和琥珀小节点，不复制报名主按钮的强调方式。

手动检查固定仓库最新正式Release，比较三段整数版本；请求有限超时、单飞、可恢复。
启动和打开帮助不联网查版本，不带任何学校凭证，不自动下载或安装。
当前1.1.0尚未发布，线上基线实查仍为1.0.2；同一候选继续沿用1.1.0，引导内容版本仍为2。

## 用户可见行为

| 情况 | 结果 |
|---|---|
| 想了解用法 | 帮助里直接看到三步，或点击重看六步引导 |
| 想查版本 | 当前版本只显示一处；点击检查更新后显示比较结果和检查时间 |
| 正式版高于本机 | 提示发现新版，用户自己去发布页选择独立EXE或完整ZIP |
| 本机候选高于正式版 | 明确预览状态和正式版号，不劝降级、不编造已发布状态 |
| 查询失败 | 局部说明原因并恢复重试按钮，不污染登录或报名结果 |
| 报名运行中 | 帮助仍可用；只禁用重看引导，查版本不打断计划 |
| 关闭再打开帮助/F5 | 沿用本实例内存里的结果或在途请求，不自动再查一次 |

## 已知限制

检查依赖GitHub可达性与其限流策略；失败可直接查看发布页。只认正式三段版本，不自动切换到预发布渠道。
结果仅代表显示时间的那次查询，不持续监控。学校真实报名和用户视觉接受仍需要单独确认。

## 变更方式

改界面同步 `local/ui/` 与本规范；改版本比较同步 `local/update_check.py` 和对应单测；
改桥接同步 `local/app.py`、UI事件与测试；正式发布继续走既有用户授权和发行门禁。
