## 1. 一个入口完成辅助任务

用户的目标是知道怎么用、重看操作引导、找版本或本机数据。这些低频任务彼此相邻，
当前内容能放进一个紧凑弹窗，不需要用户先分辨「说明」与「更多」。

| 位置 | 内容 |
|---|---|
| 顶栏「帮助」 | 问号 SVG + 文字；可访问名称为「帮助：使用说明、版本更新与本机数据」 |
| 上半部 | 三步使用说明（登录账号 / 设置报名计划 / 查看报名结果）、唯一的「重看引导」按钮、适用范围与学校结果提醒 |
| 下半部 | 当前版本、检查更新、前往下载页、本机数据目录 |
| 六步引导 | 保留既定顺序与高亮锚点；从帮助重播，退出后焦点回顶栏「帮助」 |

未登录、加载失败、组件错误和计划运行中都能打开帮助。运行中只禁用重播，
按钮写「计划结束后可重看引导」；其余辅助操作保持可用，不打断计划。

## 3. 三步说明与六步引导

三步正文由后端 `Api.help()` 与前端 `DEFAULT_HELP` 同源契约约束（逐字段一致，
`test_ui_contract` 有真实求值断言）：

1. **登录账号**：选择「登录」，在打开的浏览器中完成登录。下次启动会检查已保存的登录状态；
   只有提示失效时才需要重新登录。
2. **设置报名计划**：选择活动，设置尝试时长和最多提交次数，再选择「开始报名计划」；
   预报名会在开放后尝试提交，已开放活动会在计划启动后尝试提交。
3. **查看报名结果**：运行期间可最小化窗口，但需保持电脑唤醒与联网；
   结束后查看各活动的报名结果；开始计划不代表报名成功。

面板尾注写明适用范围：「适用于天津市大学软件学院（天软）专升本学生使用的活动中心。
活动要求与报名结果以学校活动页为准。」——主流程不重复人群介绍。

六步顺序仍为登录账号、查看活动、筛选活动、选择活动、设置并开始、查看结果；
现行正文见 `local/ui/app.js` `TOUR_STEPS`（术语与 [copywriting.md](copywriting.md) 同源）。
`TOUR_VERSION=2` 不因本轮入口合并再升。说明里的重播先关闭帮助、把焦点还给顶栏，
再开始第一步；完成或跳过后返回同一入口。窄窗仍采用既有底部说明条降级。

## 4. 「检查更新」与「前往下载页」各做什么

「检查更新」只比较当前版本与 GitHub 最新**正式**发布；「前往下载页」只打开固定网页，
不叫自动更新，也不把打开网页说成更新成功。
启动、打开帮助、刷新活动、重开帮助与 F5 均不会自行发起版本查询。

| 状态 | 可见反馈与动作 |
|---|---|
| 未检查 | 「尚未检查」；可点检查更新 |
| 检查中 | 「正在检查…」；按钮禁用，防重复请求 |
| 有新版 | 「发现新版本 X」；可查看发布页 |
| 相同 | 「当前为最新正式版」 |
| 当前高于正式 | 「当前为预览版本，最新正式版 X」；不提示降级 |
| 没有正式发布 | 「暂无正式发布」 |
| 失败 | 「暂时无法检查更新」与分类原因；可重试或查看发布页 |

结果附本次检查时间，表示该时刻的结论。不能把旧结果当作持续在线监控。
远端版本按三段整数比较，不按字符串排序；草稿、预发布、非法版本与畸形响应不得冒充最新版。

- 一次点击一次 GET，固定官方仓库接口，8 秒网络超时、256KiB 响应上限，无自动重试。
- 不携带学校凭证，不访问学校接口，不下载或安装，不接受任意远端 URL。
- 后端异步单飞，前后端用 `request_id` 对应；迟到的其他请求结果不能覆盖当前状态。
- F5 只读后端内存快照，恢复在途或已完成结果；新实例从未检查开始。
- 桥接失败或丢事件也会结束检查中，前端 15 秒兜底恢复按钮；不会改登录态、组件横幅或报名结果。

## 5. 局部反馈和键盘边界

数据目录或发布页打不开，只在帮助内解释原因与下一步；发布页失败提供固定地址供复制。
不额外弹结果框、不刷报名记录、不把辅助操作错误写成登录或网络结论。

原生 dialog 提供 Tab 焦点约束，Esc 关闭；Enter/Esc 不触发背景开始、清空或停止。
六步引导的 Tab 首尾循环、快捷键隔离、跳过和忙时暂停规则沿用
[决策 009](../decisions/009-replayable-product-tour.md)。

关闭帮助、跳过/完成引导后，焦点返回打开它的入口（`#btn-help` 或原焦点元素）；
「重看引导」按设计先关闭帮助面板，再启动引导，结束后同样把焦点还回入口。

**结果未确认的动作放在结果框**：标题「结果未确认，请勿重复启动」+ 唯一的只读
「重新确认」按钮；它只会重查 `start_request_state`，不会重发 `start_plan`。
报名结果「待核对」的下一步是打开学校活动页核对，不放进帮助面板，也不新增
第二个设置入口。

大屏地点展开按钮与表格地点共用键盘口径：可 Tab 聚焦，Enter/Space 展开/收起，
`aria-expanded` 反映状态，展开不夺取焦点、不覆盖下一条。

## 6. 版本和验收层次

- 软件当前是 **1.1.1 未发布候选**（1.1.0 已发布）；同一候选的返修与验收轮不升版。
- 实现与隔离验证看本轮结果及 [当前界面截图](../current-ui/README.md)；
  自动化、浏览器、离线 EXE 探针和用户实机验收分别记录。
- 用户对视觉与真实学校流程的验收仍待确认，本轮不代表正式发布。
- 登录估算、双模式、冲突、重试、真实 checkpoint、签到/签退三态和停止链不因帮助合并改变。
