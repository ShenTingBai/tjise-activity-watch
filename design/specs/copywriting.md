# 规范 · 界面文案（copywriting）

> 汇总全界面短文案规则。基线来自 `docs/UI_SPEC.md` §6 与现行 `local/ui/`；
> 本页是设计口径，不是逐字冻结——改措辞不丢信息即可，信息量以 UI_SPEC §6 的必须保留信息点为准。

## 总规则

1. **中文、第二人称、短句**；不用「请」「您」，不用感叹号堆情绪，不道歉。
2. **一个动作从头到尾一个名字**：登录 →「正在登录」→「登录好了」；停止 →「正在停止…」→「已停止」；
   预报名 →「等开放」→「报名成功」。
3. **错误回答两件事**：发生了什么 + 现在能做什么。
4. **说估算就写「约」**：「约剩 N 小时」「约到 xx 过期」——登录寿命是实测估算，不是保证值。
5. **不写技术词**：token/接口/子进程/退出码 → 登录态 / 学校站点 / 脚本。

## 用词对照

| 不写 | 写 |
|---|---|
| token、会话 | 登录态 |
| 接口、API | 学校站点 |
| 详情页 | 活动页 |
| 子进程、任务队列 | 脚本 |
| 日志 | 运行记录 |
| 退出码 N | （归因后的原因） |

## 分场景现行用词

### 登录（两个词不混用）

| 场景 | 文案 |
|---|---|
| 从没登录过 | 「登录」；胶囊「未登录」 |
| 真实失效（4001） | 「重新登录」；胶囊「登录态失效」 |
| 启动校验中 | 「正在检查登录态」——不得提前写「登录有效」 |
| 网络异常 | 「暂时无法确认登录态」+ 点「刷新」重试；**不说过期、不逼重登、不清登录** |
| 复用成功 | 「已复用本机登录态」 |
| 登录结束 | 「登录好了 · 约 N 小时内有效」/「登录没完成」 |

**红线**：unknown 一律不得说成「过期 / 失效」；同屏不得重复出现两条重登录文案。

### 活动模式（三个词不混用）

| 模式 | 文案 |
|---|---|
| 未来开放 | 「预报名」 |
| 已开放未截止 | 「立即报名 / 抢名额」 |
| 已截止 | 「已截止」+ 拒绝提示带活动名与截止时间 |

**红线**：「预报名」不用于已开放场次，「立即报名」不用于未来场次；混合计划里逐场标各自模式。

### 重试与提交

「第 N 次提交 · 〈最近原因〉 · 重试截止 〈时间〉 · 报名截止 〈时间〉」；
只有真正发起的提交才计数；不显示「3/10」这种虚构总数；策略档位固定叫
「2 分钟 / 10 分钟 / 30 分钟 / 1 小时 / 直到报名截止」，次数「0=不限」。

### 停止

「停止计划」（二次确认）→「正在停止…」→「已停止」/ 单场「已取消」；
停止是中性词，不写「失败」；已提交场次照常显示真实结果。

### 成功 / 失败

| 场景 | 文案 |
|---|---|
| 成功 | 「报名成功：〈活动名〉」+ 建议去活动页确认一眼 |
| 失败 | 「没抢到：〈归因后的原因〉」，原因可能是名额已满 / 页面还没放开 / 登录态失效 / 连不上学校站点；必带停止条件（达到最大提交次数 / 重试时长到了 / 报名已截止） |
| 学校原话 | 归因不命中时显示学校原话，不说错话 |

### 网络与时间线

| 场景 | 文案 |
|---|---|
| 断网 | 「网络断开了」/「连不上学校站点」+ 给「刷新」 |
| 时间线未发生节点 | 「待启动」「待打开」「待发生」——**不得**显示估算时间冒充事件 |
| 参考时间 | 「原定开放」「本次执行」「本次重试到」；已过去的历史时间显示完整日期 |
| 字段未知 | 「签到待说明」「签退待说明」（可合并「签到/签退待说明」）——不写「无需」 |
