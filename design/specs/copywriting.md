# 规范 · 界面文案（copywriting）

> 汇总全界面短文案规则。基线来自 `docs/UI_SPEC.md` §6 与现行 `local/ui/`；
> 本页是设计口径，不是逐字冻结——改措辞不丢信息即可，信息量以 UI_SPEC §6 的必须保留信息点为准。

## 总规则

1. **中文、第二人称、短句**；不用「请」「您」，不用感叹号堆情绪，不道歉。
2. **一个动作从头到尾一个名字**：登录 →「正在登录」→「登录好了」；停止 →「正在停止…」→「已停止」；
   预报名 →「等开放」→「报名成功」。
3. **错误回答两件事**：发生了什么 + 现在能做什么。
4. **说估算就写「约」**：「约剩 N 小时」「约到 xx 过期」——登录寿命是实测估算，不是保证值。
5. **不写技术词**：token/接口/子进程/退出码 → 登录态 / 学校站点 / 脚本。

## 用词对照

| 不写 | 写 |
|---|---|
| token、会话 | 登录态 |
| 接口、API | 学校站点 |
| 详情页 | 活动页 |
| 子进程、任务队列 | 脚本 |
| 日志 | 运行记录 |
| 退出码 N | （归因后的原因） |

## 分场景现行用词

### 登录（两个词不混用）

| 场景 | 文案 |
|---|---|
| 从没登录过 | 「登录」；胶囊「未登录」 |
| 真实失效（4001） | 「重新登录」；胶囊「登录态失效」 |
| 启动校验中 | 「正在检查登录态」——不得提前写「登录有效」 |
| 网络异常 | 「暂时无法确认登录态」+ 点「刷新」重试；**不说过期、不逼重登、不清登录** |
| 复用成功 | 「已复用本机登录态」 |
| 登录结束 | 「登录好了 · 约 N 小时内有效」/「登录没完成」 |

**红线**：unknown 一律不得说成「过期 / 失效」；同屏不得重复出现两条重登录文案。

### 活动模式（三个词不混用）

| 模式 | 文案 |
|---|---|
| 未来开放 | 「预报名」 |
| 已开放未截止 | 「立即报名 / 抢名额」 |
| 已截止 | 「已截止」+ 拒绝提示带活动名与截止时间 |

**红线**：「预报名」不用于已开放场次，「立即报名」不用于未来场次；混合计划里逐场标各自模式。

### 重试与提交

「第 N 次提交 · 〈最近原因〉 · 重试截止 〈时间〉 · 报名截止 〈时间〉」；
只有真正发起的提交才计数；不显示「3/10」这种虚构总数；策略档位固定叫
「2 分钟 / 10 分钟 / 30 分钟 / 1 小时 / 直到报名截止」，次数「0=不限」。

### 停止

「停止计划」（二次确认）→「正在停止…」→「已停止」/ 单场「已取消」；
停止是中性词，不写「失败」；已提交场次照常显示真实结果。

### 成功 / 失败

| 场景 | 文案 |
|---|---|
| 成功 | 「报名成功：〈活动名〉」+ 建议去活动页确认一眼 |
| 失败 | 「没抢到：〈归因后的原因〉」，原因可能是名额已满 / 页面还没放开 / 登录态失效 / 连不上学校站点；必带停止条件（达到最大提交次数 / 重试时长到了 / 报名已截止） |
| 学校原话 | 归因不命中时显示学校原话，不说错话 |

### 空列表：已知零 ≠ 未知

| 状态 | 文案 |
|---|---|
| 登录有效 + 学校成功返回 0 场 | 「学校当前没有返回活动」+「稍后点「刷新」再看」；**不得**再给登录 / 重新登录引导 |
| 从没登录过 | 「登录后查看活动」+ 点「登录」 |
| 确认失效（4001） | 「登录态失效，先重新登录」 |
| 无法确认（unknown） | 「暂时无法确认登录态」+ 刷新；**不说过期、不逼重登** |
| 还没成功拉到过 | 「还没拉到活动列表」；不谎称学校零活动 |

指标口径：成功返回 0 场 → 列表与可报名都写 `0`；未拉到或失败 → `—`。

### 选择与开始（不许暗示「选中即执行」）

- 选中活动 = 放进草稿，**不会自己开始**；唯一的开始动作是点「开始报名计划」。
- 不写「选中后马上执行」「到点自动开始」这类把选择等同于启动的说法；
  写「先选中，到点由计划开始」「也要先选中、再点「开始报名计划」才执行」。

### 任务结果 vs 计划结果

- 任务卡与运行记录说**这一场**：报名成功 / 没抢到 / 已取消 / 已报名。
- 整块大屏与结果框说**整个计划**：报名计划完成 / 部分完成 / 没有成功 / 已停止。
- 计划运行中不拿单场结论写计划结论；「停止」只结束本机任务，**不是**撤销学校报名。

### 运行阶段：预热 ≠ 已提交

| 真实情况 | 写 | 别写 |
|---|---|---|
| 预报名还没开放，worker 已在提前开页 | 「提前准备，等到 HH:MM:SS 开放」「等待开放」 | 「正在提交」「第 1 次提交」 |
| 已开放，但还没有一次真正的提交 | 「准备报名」「已开放，正在准备提交」 | 「等待开放」（已经开了） |
| 已经真正发起过提交 | 「第 N 次提交 · 最近原因 · 重试到 HH:MM」 | 「准备中」 |
| 截止未知（没有绝对截止、也没有启动参考点） | 「重试截止待定」「等待提交结果」 | 「00:00:00」「还剩 0 秒」 |

**红线**：`attempts` 是唯一「已提交」证据；worker 提前启动只是准备，不能算作已提交。

### 空态动作：重试就重试，清筛选就清筛选

| 空态原因 | 按钮 | 点击后必须发生 |
|---|---|---|
| 列表请求失败（含桥接异常，且有缓存） | 「重试」 | 真的再发 check / list，不能只清筛选把错误藏掉 |
| 筛选后没有结果 | 「清除筛选」 | 只重置 6 个筛选键，策略/引导/日志偏好不动 |
| 还没拉到 / 登录相关 | 「刷新」 | 重新拉列表 |

**红线**：按钮含义由渲染时的动作意图决定，不按「有没有缓存数据」或按钮文字去猜。

### 登录检查中：不说有效，也不逼重登

| 状态 | 写 |
|---|---|
| `checking` | 「正在检查登录态」+「稍等一下；这段时间先不用重新登录」 |
| 结论缺失 / 无法判定 | 「暂时无法确认登录态」+ 刷新（按 unknown 处理，不得默认成有效） |
| 确认有效 | 才能说「登录是有效的」 |

### 辅助入口：统一帮助（决策011）

| 位置 | 用词 | 别写 |
|---|---|---|
| 顶栏唯一入口 | 「帮助」 | 并列「说明」「更多」「设置」 |
| 对应弹窗标题 | 「使用帮助」 | 再创建第二个模态 |
| 重播动作 | 「重看引导」 | 「重新播放教程」「再看一次」 |
| 版本比较 | 「检查更新」 | 「立即更新」（未提供自动安装） |
| 外链动作 | 「查看发布页」 | 把打开链接说成检查成功 |
| 当前候选高于正式版 | 「当前为预览版本，最新正式版 X」 | 「请降级」「1.1.0已发布」 |
| 检查失败 | 「暂时无法检查更新」+ 原因 | 「已经最新」 |
| 结论时效 | 本次检查时间 | 省略时间却暗示持续监控 |

### 网络与时间线

| 场景 | 文案 |
|---|---|
| 断网 | 「网络断开了」/「连不上学校站点」+ 给「刷新」 |
| 时间线未发生节点 | 「待启动」「待打开」「待发生」——**不得**显示估算时间冒充事件 |
| 参考时间 | 「原定开放」「本次执行」「本次重试到」；已过去的历史时间显示完整日期 |
| 字段未知 | 「签到待说明」「签退待说明」（可合并「签到/签退待说明」）——不写「无需」 |
