# 本机版界面设计任务书（给 Codex）

这份文档只讲「界面该长什么样、要考虑什么」，实现契约在最后一节。改界面时**只动
`local/ui/index.html`、`local/ui/styles.css`、`local/ui/app.js` 的展示层**；
`local/app.py` 里的方法名与返回结构是接口，不要改。

---

## 1. 背景

一个校园活动「到点自动报名」工具，只服务天津市大学软件学院（天软）专升本的学生。
使用方式是：**下载绿色版 zip → 解压 → 双击 exe/bat → 出窗口**。用的人大多是同学，
不是开发者，默认不会看 README，也没有耐心调参数。

窗口背后是 `grab.py`（登录、拉活动列表、到点抢报名）。界面现在用 pywebview +
WebView2 渲染，所以可以按现代 Web 的做法做视觉，但必须离线可用。

## 2. 目标（按优先级）

1. **第一眼就知道现在什么状态**：登录有没有过期、有多少可报的活动、下一个开放的还有多久。
2. **三步之内完成一次抢报名**：选活动 → 点按钮 → 等结果。
3. **失败要能看懂**：没抢到必须给出人话原因（名额满、页面没放开、登录失效、网络不通）。
4. **不吓人**：这是给同学用的工具，界面气质要克制、干净，不要像后台管理系统。

## 3. 用户会遇到的真实场景（设计要覆盖）

| 场景 | 界面该做什么 |
|---|---|
| 第一次打开，没登录过 | 明确引导去点「登录」，而不是显示一堆"接口异常" |
| 登录态还有 3 小时 | 状态胶囊显示剩余时间，临近过期给视觉提醒（橙色） |
| 活动列表几百条，只有几条能抢 | 默认只看未报名，支持和关键词/状态/时间组合筛选 |
| 活动还没到开放时间 | 「距开放」每秒走字，让人知道程序在等 |
| 报名开放那一刻 | 忙碌态清晰（按钮禁用 + 进度感），不要让人以为卡死 |
| 抢成功 | 强反馈（绿），并提示"去活动页确认一眼" |
| 没抢到 | 强反馈（红）+ 具体原因 + 下一步建议 |
| 电脑锁屏/最小化后回来 | 状态仍准确（不能停留在"正在抢"的假象） |
| 网络断了 | 错误信息说清是网络问题，不要笼统写"失败" |

## 4. 现有结构（可以重排，但信息不能少）

```
┌────────────────────────────────────────────────────────────┐
│ 标题 + 副标题            [状态胶囊] [使用说明] [刷新] [登录] │
├────────────────────────────────────────────────────────────┤
│ [搜索框] [全部|未报名|已报名] [时间▾] [排序▾]        共 N 个 │
├────────────────────────────────────────────────────────────┤
│ #  │ 距开放 │ 报名开始 │ 状态 │ 活动名        │ 地点       │
│    │        │          │      │               │            │
├────────────────────────────────────────────────────────────┤
│ 已选：xxx  [ ] 显示浏览器窗口           [打开数据目录]      │
│ [到点抢选中的活动] [停止]        距离开放 00:12:31          │
│ ✗ 没抢到：名额已满                                          │
├────────────────────────────────────────────────────────────┤
│ 运行日志                                     [展开] [清空]  │
└────────────────────────────────────────────────────────────┘
```

可以改的东西：区块顺序（只要不用滚动就能看到"状态 + 列表 + 主按钮"）、
表格列（地点可以合并到活动名下方做副标题）、日志默认高度、
把「显示浏览器窗口」「打开数据目录」收进二级菜单或图标按钮。

## 5. 组件与状态矩阵

必须覆盖这些状态（CSS 里已有对应的状态类，可改名但要在 `app.js` 同步）：

| 组件 | 状态 |
|---|---|
| 状态胶囊 | 未登录(灰) / 有效·约剩 N 小时(绿) / 临近过期(橙，建议剩余<2h) / 失效(红) / 进行中(蓝) |
| 主按钮 | 默认 / hover / active / disabled(未选活动 或 忙碌) / busy(可显示转圈或文案变化) |
| 表格行 | 默认 / hover / 选中 / 已报名(灰) / 空列表 |
| 筛选胶囊 | 选中 / 未选中 / hover |
| 结果条 | 成功(绿) / 失败(红) / 隐藏 |
| 日志 | 收起(6 行) / 展开(十几行) / 空 |

## 6. 数据契约（用到的字段，不要假设别的）

`api.list_activities()` → `{ok, items:[...]}`，每项：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 活动 id，抢报名时用它定位，不要依赖序号 |
| `name` | string | 活动名，可能很长（20+ 字），要能截断 + hover 显示全名 |
| `place` | string | 地点，可能为空 |
| `sign_start` | string | 报名开始，`YYYY-MM-DD HH:MM:SS`，可能为空 |
| `sign_end` | string | 报名截止，同上 |
| `act_start` | string | 活动开始时间 |
| `signed` | bool | 是否已报名 |
| `state` | string | 后端给的中文状态（如「未开放」「开放中」「已报名」） |
| `seconds_to_open` | int \| null | 距报名开放秒数，正数=未开放，≤0=已开放 |

`window.onBackend.log(line)`：一行日志（脚本原话，可能含 `[X]`/`[i]`/`▶`）。
`window.onBackend.done({ok, code, reason, label})`：一次任务结束。
`window.onBackend.state({hours_left, ok})`：登录态变化。

## 7. 文案要求

- 中文，第二人称，短句，不用「请」「您」这类客套，也不用感叹号堆情绪。
- 不说技术词：不写「token」「接口」「子进程」「退出码」；写「登录态」「活动列表」「脚本」。
- 错误信息必须回答：**发生了什么 + 现在能做什么**。
- 已有文案可沿用（见 `app.js` 的 `help()`、`setResult`、空态），可以优化但不能丢信息。

关键文案清单（设计时要留出空间）：

1. 空列表：「这里还没有活动」+「点右上角「刷新」拉一次列表；如果提示登录态失效，先点「登录」。」
2. 未登录：「未登录」/「登录态失效」+ 主按钮仍是「登录 / 重新登录」
3. 成功：「✓ 报名成功：<活动名>」，建议提示「去活动页确认一眼」
4. 失败：「✗ 没抢到：<原因>」，原因可能是「名额已满」「页面还没放开」「登录态失效」「连不上学校站点」
5. 使用说明：三步（先登录 / 选活动 / 保持在线）+ 一条边界提醒（只给自己的账号用，不要多开）

## 8. 视觉方向（建议，不是强制）

- 浅色底、白卡片、单一强调色（现在用深绿 `#1F6F4A`，可以换但要统一）。
- 字号阶梯建议 12 / 13 / 14 / 16 / 20 / 24，行高 1.5–1.7；表格正文 13px。
- 8px 栅格做间距；圆角 8（小控件）/ 12（卡片）/ 999（胶囊）。
- 阴影克制：卡片最多两层，不要外发光。
- 字体只用系统字体栈（微软雅黑 / PingFang / system-ui），**不要引外部字体**。
- 对比度按 WCAG AA（正文 ≥4.5:1）。已报名的灰字不要灰到看不见。

## 9. 技术约束（硬要求）

1. 纯静态：`index.html` + `styles.css` + `app.js`，**无构建步骤、无 npm、无 CDN**（离线运行）。
2. 渲染内核是 WebView2（Chromium 110+），可以用 flex/grid、CSS 变量、
   `dialog`、`backdrop-filter`（可选）；**不要用需要 polyfill 的新语法**。
3. 窗口最小 980×700，默认 1120×800；150% 缩放下不能错位或糊。
4. 首屏 300ms 内可见骨架；列表几百行要能顺畅滚动（必要时虚拟滚动，但别引入依赖）。
5. 键盘：F5 刷新、Enter 在表格上抢选中的、Tab 焦点可见（`:focus-visible` 描边）。
6. 不能改 `app.py` 的方法名/参数/返回结构；不能改 `grab.py`。

## 10. 验收清单

- [ ] 三种空/错状态（未登录、拉取失败、列表为空）都有明确引导
- [ ] 选行 → 主按钮可用；不选 → 禁用；忙碌 → 三个按钮状态正确
- [ ] 距开放每秒更新，且不引起整表重排/闪烁
- [ ] 成功/失败结果条颜色与文案正确，且能一眼看到
- [ ] 使用说明可反复打开（不是只弹一次）
- [ ] 日志展开/收起正常，长日志不撑破布局
- [ ] 980×700 与 1120×800、100%/150% 缩放都不出现横向滚动条
- [ ] 无外部网络请求（DevTools Network 只有本地文件）

## 附：怎么本地跑

```bat
cd local
```

## 7. 现状（脚手架已跑通，2026-10-22）

- 外壳：`local/app.py`（pywebview + WebView2），把 `grab.py` 的能力暴露成
  `window.pywebview.api.*`，把子进程输出推成 `window.onBackend.*` 事件。
- 界面：`local/ui/index.html` + `styles.css` + `app.js`，纯静态、离线可用。
- 调样式不需要登录：`python app.py --demo`（假数据，五个活动，覆盖已报名/开放中/未开放三种状态）。
- 截图办法：跑起来后按 `Win+Shift+S`，或让脚本 `ImageGrab.grab(bbox=窗口矩形)` 抓窗口。
- **坑（务必遵守）**：`app.py` 的 `Api` 实例上**不要挂公开实例属性**
  （`self.window`、`self.proc` 这类）。pywebview 注入桥接时会递归扫描非 callable 属性，
  挂上 Window/Popen 对象会让页面 `loaded` 事件不触发、界面白屏。内部状态一律用下划线开头。
- 同理，`js_api` 方法里**不要做阻塞操作**：`check` / `list_activities` 已改成"起线程 + 事件回推"，
  直接在方法里 `subprocess.run` 会让窗口"未响应"。

## 8. 已知待改进（留给设计阶段）

1. 状态列与「距开放」列信息重复（已报名/已开放 出现两次），可合并成一列语义更强的状态徽标。
2. 表格行高、字号偏小，长活动名在窄窗口会截断，可考虑两行式行高。
3. 顶部按钮组在 980px 最小宽度下略挤，可收进「更多」或改成图标。
4. 空态插画、忙碌态进度感、错误态配色还没做精细。
